# Premier League frontend data contract

Generated by `py -m scripts.generate_analytics`. The frontend can consume the
JSON files in `data/processed/analytics/` directly; it must not recalculate
league points, rates, streaks, form, or venue splits.

## Dataset inventory and relationships

All files are JSON arrays of objects. `cleaned_matches` has one row per
completed fixture. `team_match` has exactly two rows for every `MatchID` and is
the canonical team-perspective fact table. Every team summary joins on
`Season + Team`; venue summaries additionally join on `Venue`. Direct
head-to-head views can filter `team_match` by `Team + Opponent`.

The current export contains 17 datasets, each with a CSV and a JSON version:

| Dataset | Grain | Primary fields |
| --- | --- | --- |
| `cleaned_matches` | one completed fixture | `MatchID`, `Season`, `Date`, teams, scores, source metadata and source match fields |
| `team_match` | one team in one fixture | `MatchID`, `Season`, `Date`, `Team`, `Opponent`, `Venue`, team-perspective stats |
| `team_season_summary` | one team-season | results, points, goals, defence, shooting, streaks and volatility |
| `team_home_away_summary` | one team-season-venue | team summary measures by venue plus home-advantage fields |
| `attacking_summary` | one team-season | scoring and shot-efficiency measures |
| `defensive_summary` | one team-season | goals conceded, clean sheets and concession buckets |
| `winning_patterns` | one team-season | win margins and win-state patterns |
| `losing_patterns` | one team-season | loss margins and loss-state patterns |
| `form_consistency_summary` | one team-season | last five, rolling form, streaks and volatility |
| `half_time_full_time_summary` | one team-season | leads, comebacks, lost leads and preservation |
| `half_time_full_time_transition` | one half-time result row | `HTR`, `H`, `D`, `A` counts |
| `goal_distribution` | one goal bucket | `GoalBucket`, `Matches` |
| `goal_statistics` | one overall statistic | `Metric`, `Value` |
| `season_summary` | one season | coverage, completeness, rates and goal averages |
| `efficiency_correlations` | one correlation matrix row | `Metric`, `TotalGoals`, `TotalShots`, `TotalShotsOnTarget`, `TotalCorners` |
| `efficiency_outcome_comparison` | one full-time result | `FTR` and mean match totals |
| `efficiency_patterns` | one result code | dominance counts and wins/losses against statistical advantage |

## Exact field schemas

The following lists are generated from the current exports and are the source
of truth for the frontend.

### `cleaned_matches`

`MatchID`, `Div`, `Date`, `Time`, `HomeTeam`, `AwayTeam`, `FTHG`, `FTAG`,
`FTR`, `HTHG`, `HTAG`, `HTR`, `Referee`, `HS`, `AS`, `HST`, `AST`, `HF`, `AF`,
`HC`, `AC`, `HY`, `AY`, `HR`, `AR`, bookmaker/source match-stat columns from
Football-Data, `Season`, `Source`, `CollectionMethod`, `SourceURL`,
`RetrievedAt`, `SourceFile`, `total_goals`, `goal_difference`, `total_shots`,
`total_shots_on_target`, `total_corners`, `high_scoring`.

The bookmaker columns are preserved source fields, not dashboard calculations.
They may differ by season and should be treated as optional passthrough data.
The generated aliases `total_goals`, `goal_difference`, `total_shots`,
`total_shots_on_target`, `total_corners`, and `high_scoring` are match-level
derived fields.

### `team_match`

`MatchID`, `Season`, `Date`, `Team`, `Opponent`, `Venue`, `GoalsFor`,
`GoalsAgainst`, `Result`, `Points`, `HTGoalsFor`, `HTGoalsAgainst`, `HTResult`,
`ShotsFor`, `ShotsAgainst`, `ShotsOnTargetFor`, `ShotsOnTargetAgainst`,
`CornersFor`, `CornersAgainst`, `GoalDifference`, `ShotDifference`,
`SOTDifference`, `LeadingAtHT`, `TrailingAtHT`, `DrawingAtHT`, `CleanSheet`,
`Scored`.

`Result` is from `Team`'s perspective (`H` win, `D` draw, `A` loss). `Points`
is 3, 1, or 0. Optional shot, target, corner and half-time fields are null
when either source observation is unavailable; they are never zero-filled.

### Team summary fields

The following fields are used by `team_season_summary` and, except for streak
fields, by `team_home_away_summary`:

| Field | Definition | Denominator/null rule |
| --- | --- | --- |
| `Matches` | team-perspective fixtures | count of team rows |
| `Wins`, `Draws`, `Losses` | result counts | count by `Result` |
| `WinRatePct`, `DrawRatePct`, `LossRatePct` | result count / `Matches × 100` | null only when no matches |
| `Points` | sum of 3-1-0 points | no denominator |
| `PointsPerMatch` | points / matches | null when matches = 0 |
| `GoalsScored`, `GoalsConceded` | sum of goals for/against | no denominator |
| `GoalsScoredPerMatch`, `GoalsConcededPerMatch` | goals / matches | null when matches = 0 |
| `GoalDifference` | goals scored − goals conceded | no denominator |
| `CleanSheets` | matches with `GoalsAgainst = 0` | count |
| `CleanSheetRatePct` | clean sheets / matches × 100 | null when matches = 0 |
| `FailedToScoreRatePct` | `GoalsFor = 0` / matches × 100 | null when matches = 0 |
| `Conceded1PlusRatePct`, `Conceded2PlusRatePct`, `Conceded3PlusRatePct` | matches conceding at least 1, 2, or 3 / matches × 100 | null when matches = 0 |
| `Conceded0Count` … `Conceded4PlusCount` | conceded-goal buckets 0, 1, 2, 3, 4+ | counts |
| `TotalShots`, `TotalShotsOnTarget` | sum of observed shots/targets | null if no observation exists |
| `ShotsPerMatch`, `ShotsOnTargetPerMatch` | observed total / matches with observations | null if no observations |
| `ShotAccuracyPct` | shots on target / shots × 100 | null when shots are unavailable or zero |
| `ShotConversionPct` | goals / shots × 100 | null when shots are unavailable or zero |
| `GoalsPerShotOnTarget` | goals / shots on target | null when targets are unavailable or zero |
| `GoalDifferenceStdDev` | sample standard deviation of match goal difference | 0 for one match; null only with no rows |
| `PerformanceVolatility` | sample standard deviation of match points | 0 for one match; null only with no rows |
| `LongestWinningStreak`, `LongestLosingStreak`, `LongestUnbeatenStreak`, `LongestWinlessStreak` | maximum chronological consecutive run | ordered by `Date`, then `MatchID` |

`attacking_summary` contains the attacking subset: `Season`, `Team`,
`GoalsScored`, `GoalsScoredPerMatch`, `TotalShots`, `TotalShotsOnTarget`,
`ShotsPerMatch`, `ShotsOnTargetPerMatch`, `ShotAccuracyPct`,
`ShotConversionPct`, `GoalsPerShotOnTarget`.

`defensive_summary` contains `Season`, `Team`, `GoalsConceded`,
`GoalsConcededPerMatch`, `Conceded1PlusRatePct`, `Conceded2PlusRatePct`,
`Conceded3PlusRatePct`, `CleanSheets`, `CleanSheetRatePct`,
`Conceded0Count`, `Conceded1Count`, `Conceded2Count`, `Conceded3Count`,
`Conceded4PlusCount`, `GoalDifferenceStdDev`.

## Pattern, form and season fields

`winning_patterns` fields are `Season`, `Team`, `Wins`, `Margin1`, `Margin2`,
`Margin3Plus`, `WithoutConceding`, `DespiteShotDisadvantage`,
`DespiteSOTDisadvantage`, `AfterTrailingAtHT`, `AfterDrawingAtHT`,
`AverageMargin`, plus the corresponding `...RatePct` fields. Rates use wins
as denominator.

`losing_patterns` fields are `Season`, `Team`, `Losses`, `Margin1`, `Margin2`,
`Margin3Plus`, `AfterDrawingAtHT`, `DespiteScoring`, `DespiteShotAdvantage`,
`DespiteSOTAdvantage`, `AfterLeadingAtHT`, `AverageMargin`, plus the
corresponding `...RatePct` fields. Rates use losses as denominator. A heavy
defeat is `Margin3Plus`; “loss despite shot dominance” is strictly
`ShotDifference > 0` for the losing team.

`form_consistency_summary` fields are `Season`, `Team`, `LastFiveResults`,
`LastFivePoints`, `RollingPointsPerMatch`, `RollingGoalsScored`,
`RollingGoalsConceded`, `LastFiveMatches`, `GoalDifferenceStdDev`,
`LongestWinningStreak`, `LongestLosingStreak`, `LongestUnbeatenStreak`, and
`LongestWinlessStreak`. Last-five rows are the chronologically latest five
completed team fixtures; rolling goals are per match.

`half_time_full_time_summary` fields are `Season`, `Team`, `HalfTimeLeads`,
`PreservedHalfTimeLeads`, `LeadPreservationRatePct`, `ComebackWins`,
`ComebackDraws`, `ComebackSuccessRatePct`, `LostLeads`, and `LostLeadRatePct`.
Lead preservation is preserved leads / half-time leads. Comeback success is
comeback wins / matches trailing at half-time. Lost-lead rate is lost leads /
half-time leads. Missing half-time data is excluded from these denominators.

`season_summary` fields are `Season`, `CompletedMatches`,
`ParticipatingTeams`, `ExpectedMatchesForParticipatingTeams`,
`IsCompleteSeason`, `GoalsPerMatch`, `HomeWinRatePct`, `DrawRatePct`,
`AwayWinRatePct`, `HomeGoalsPerMatch`, `AwayGoalsPerMatch`, and `TeamRecords`.
Completeness is based on observed fixtures and participating teams; cumulative
comparisons should use `CompletedMatches` and the boolean flag.

## Efficiency and goal fields

`goal_distribution` contains `GoalBucket` values 0, 1, 2, 3, and `4+`, with
`Matches` counts. `goal_statistics` contains `Metric` values `Mean`, `Median`,
`Mode`, `StandardDeviation`, and `HighScoringRatePct` with `Value` values.

`efficiency_correlations` has fields `Metric`, `TotalGoals`, `TotalShots`,
`TotalShotsOnTarget`, and `TotalCorners`. It is a Pearson correlation matrix
for the four numeric fields, with `Metric` preserving the row label. It describes association
only. `efficiency_outcome_comparison` contains `FTR`, `TotalGoals`,
`TotalShots`, `TotalShotsOnTarget`, and `TotalCorners` means by result. The
`efficiency_patterns` fields are `Result`, `Matches`, `ShotDominance`,
`SOTDominance`, `WinsDespiteShotDisadvantage`, `LossesDespiteShotAdvantage`,
`WinsDespiteSOTDisadvantage`, and `LossesDespiteSOTAdvantage`.

## Filters and frontend usage

The canonical filters are exact `Season`, `Team`, `Opponent`, `Venue` (`Home`
or `Away`), `start_date`, and `end_date`. Apply them to `team_match` first,
then aggregate the filtered rows with the already-defined fields; or use the
pre-aggregated tables when the requested filter matches their grain. Date
comparisons are inclusive and ISO-compatible (`YYYY-MM-DD`). Filtering must
not treat null optional observations as zero.

Example JSON object from `team_match`:

```json
{
  "MatchID": 1,
  "Season": "2023/24",
  "Date": "2023-08-11T00:00:00",
  "Team": "Manchester City",
  "Opponent": "Burnley",
  "Venue": "Away",
  "GoalsFor": 3,
  "GoalsAgainst": 0,
  "Result": "H",
  "Points": 3,
  "ShotsFor": 17,
  "ShotsOnTargetFor": 8,
  "CleanSheet": true,
  "Scored": true
}
```

JSON nulls are genuine missing observations. CSV and JSON exports were checked
for equal row counts for all 17 datasets. The frontend should display null as
“Not available” rather than zero.
